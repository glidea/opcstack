# 支付

在 **后台 > Configuration > Payment** 管理支付渠道和商品。支付配置保存在 D1，保存后对新请求立即生效。

启用支付前先创建商品。一次性商品在支付成功后发放一次积分。订阅商品需要套餐名、升级等级和每期积分。商品名称、价格、币种和计费周期以支付渠道后台为准。

每个启用的渠道都需要 API Key 和 Webhook 签名密钥。把页面展示的 Webhook URL 配置到渠道后台。测试模式和正式模式必须使用对应环境的凭据。

商品编辑使用乐观版本控制。过期版本更新或删除仍被有效订阅引用的商品会被拒绝，不会覆盖当前配置。

密钥保存后不再显示明文。替换 Webhook 密钥后，下一个请求立即使用新密钥校验。

Provider 配置和商品独立保存。商品操作成功后只更新当前页面中的目标商品，删除前必须确认。其他浏览器已经修改同一商品时，需要刷新当前数据后重新编辑。
